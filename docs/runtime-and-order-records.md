新模块 `backend/post_payment.py` 对应脚本 `finishPayment`、`confirmActivation`、`disableRenewal`：

1. 先保存收尾进度，再访问符合本单 checkout ID、账号和处理实体的 HTTPS `chatgpt.com/checkout/verify` 回跳地址。优先使用已有响应中的有效地址，否则采用脚本的标准回跳地址。访问回跳不等于订阅生效，也不发送付款确认/批准请求。
2. 查询订阅最多 5 次，间隔 2 秒；401 才刷新 Session 并重查。只有 GET 订阅接口返回精确的 `404 + {"detail":"No subscription found for account"}` 才作为到账延迟继续查询。普通 404、403、响应格式错误仍中止核实。
3. 按脚本的套餐别名和有效期/续费字段确认生效，不再只看 `is_active`，不再忽略套餐不符。本系统 `pro` 对应脚本 `pro20x`，`team_premium` 对应 `team5x`。
4. 保留续费的订单到此完成；关闭续费的订单先刷新 Session，然后查询真实续费状态。明确关闭则直接完成，缺失或冲突则待核实，不发送取消请求。
5. 每次取消前持久保存 `cancellation_requested`。取消请求失败后先查询状态：已经关闭就结束；只有明确仍开启，且原错误属于脚本的网络错误、408、429、500、502、503、504 白名单时，才允许第二次取消请求。成功提交后最多查询 5 次、间隔 2 秒，确认关闭才显示“自动续费已关闭”。
6. 刷新仍使用 `/api/auth/session?refresh=true&reason=token_expired`，移除 Bearer 头、携带已有 Session Cookie，检查返回账号并保存新 accessToken 和轮换后的会话 Cookie。HTTP 403 / HTML 挑战按真实 HTTP 状态记录并停在待核实；本次没有改变上游访问权限或挑战处理。

Python 适配继续使用项目现有 `proxy_client`，保留本地前置代理与正式环境的原有分支。HTTP 传输没有替换为 Go 包的浏览器/TLS 实现。每次付款后业务请求前后，使用同一 client 探测出口，对照**本单** `order_proxy_sessions` 保存的原始 IP，并校验原会话有效期。恢复时还核对保存的 endpoint、IP 和过期时间。会话过期、记录变更或出口变化就停止；不分配新代理、不更新原始 IP、不回退直连。回跳和 API 请求均不自动跟随重定向。

新增 `subscription_followups` 表，使用现有主密钥加密保存收尾 checkpoint（回跳地址、套餐、凭据、原代理会话及收尾状态），不保存卡信息或付款提交参数。checkpoint、订阅/续费状态、业务事件和关键技术日志同事务保存；订单级 PostgreSQL advisory lock 防止 worker 与恢复命令并发执行。收尾错误不会把已成功的付款改成失败，不会改动余额、冻结、账本或付款凭据，已确认的订阅生效状态也会保留。

显式恢复入口：`.venv/Scripts/python.exe scripts/recover_post_payment.py ORDER_ID`。仅接受有持久付款成功凭据及新收尾 checkpoint 的订单，继续核实/关闭续费；完成的 checkpoint 再调用不外发请求。没有新增自动重放调度，不为历史订单伪造 checkpoint，没有重跑此前成功的真实订单。

监控新增回跳访问、续费状态查询和原出口比对记录，继续记录 HTTP 状态/耗时与固定错误分类，不保存原始响应、Token、代理密码或完整回跳地址。付款成功但收尾仍在进行/待核实时，不再显示“订阅办理完成”。

## 代理链仅限本机

本机 `.env` 增加：

```dotenv
LOCAL_EGRESS_PROXY=http://127.0.0.1:7897
LOCAL_EGRESS_SOCKS_PROXY=socks5h://127.0.0.1:7897
```

本机 Mihomo 的混合端口已验证同时支持 HTTP 和 SOCKS5。

- 代理测试及订单出口探测：Python → 本机 HTTP 代理隧道 → 配置的远端代理 → 目标。
- 提链 curl 请求：本机 SOCKS5 前置代理 → 配置的 HTTP/HTTPS 代理 → 目标。
- 订阅付款 requests 会话（初始化、税费、付款资料、确认、批准、结果查询，以及复用该会话的请求）：同样使用本机 HTTP 隧道 → 配置的远端 HTTP/HTTPS 代理 → 目标。`payment_transport.py` 仅替换底层建连，保留 urllib3 原有远端代理认证、CONNECT 和 TLS 校验；禁止环境代理覆盖本单代理，失败不回退直连。关闭续费和订阅生效查询沿用已有 httpx 本机链。
- 未设置 `LOCAL_EGRESS_PROXY` 时，沿用服务器直接连接所选远端代理的方式。正式美国服务器不要复制本机 `.env`，也不要设置上述变量。
- 后台代理资源和账号密码未改成 localhost；本机代理只控制第一段网络连接。
- Mihomo Fake-IP 导致系统 DNS 返回 `198.18.*`。启用本机代理链时，通过本机代理查询加密 DNS，验证并固定远端代理的公网 IP，再建立隧道。保留公网地址校验，不直接放行 Fake-IP、内网或回环代理目标。
- 链路失败明确失败，不回退为直连。curl 的前置链目前适配远端 HTTP/HTTPS 代理；远端 SOCKS 代理在此提链模式下明确拒绝，避免静默绕过本机代理。

## 账单资料进入实际付款参数

`_pick_billing` 从系统 `billing.country` 取得国家，随机选取启用且非测试的系统资料；国家、州、城市、街道、邮编、姓名、邮箱、资料编号保存到本单快照。

`_payment_billing` 校验并读取本单快照。在真实付款代码中，该地址传给 `update_tax_region`，以及 `build_payment_method_form(address=...)`；姓名和邮箱也来自同一份快照。资料缺失时在请求前失败，不从当前系统配置、订阅地区或示例地址补造。

后台返回 `region`，同时保留 `state_code` 兼容字段。旧单已保存的 NH、OR 等州代码直接显示；旧快照漏存的国家按本项目原来固定 US 的规则补显，并注明来源，不改写历史数据库快照。新单完整保存国家。
