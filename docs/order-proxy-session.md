# 订单代理会话与出口检测

2026-11-03 按用户要求，订阅办理和结账链接的业务流程不再发起出口 IP 查询，也不比较前后出口 IP。

- 每单仍按订阅地区领取代理并生成原有厂商 session/sid，保存到 order_proxy_sessions，后续提链、付款、订阅核实、授权刷新及取消续费复用该订单已保存的代理。
- 保留会话过期和代理地址被替换的本地校验。它们只检查订单记录，不向外请求出口信息。
- generator 不再查询直连/代理 IP，不再按探测结果覆盖订单地区和币种。长短链及套餐请求本身保持原有规则。
- 付款后收尾不要求 expected_ip。历史数据库字段和检查点允许保留该字段，但不再读取或比较。
- 账单抽取、付款提交、费用结算及后台开关保持原逻辑。代理管理的检测和评分是独立操作，继续可用。

固定的是订单的代理会话；代理厂商能否在整个会话内维持相同实际出口取决于其服务，本系统不再主动验证。

验证使用临时数据库、模拟 HTTP 和禁止外网的提链参数矩阵：35 项后端集成测试、16 项付款后测试、8 组套餐/长短链组合通过。没有发起真实付款。部署范围仅为本地。
