# Team团队订阅

当前 `cslive_go_direct_pay` 流程将 Team 标准和高级合并为 `team`（Team团队订阅）。新订单及公开目录不再单列 `team_premium`，历史套餐行、订单、服务费、账户专属价及启停配置保留；其他流程继续原规则。

页面普通席位与高级席位各自允许为0，合计须为2～100。API `seats` 仍表示总数，`premium_seats` 表示其中高级数；Team省略时分别2和0。执行时传Go普通数 `seats-premium_seats`、高级数 `premium_seats`，不再强行各加最低席位。上游仍使用 `chatgptteamplan`，seat_type分别default和prolite。页面不再要求或发送团队空间名称；Go沿用既有固定名称Team。

可选 `promo_code` 只用于Team的这条流程。值须为UTF-8且不超过256字节、无控制字符；去除两侧空格。加密保存在本单credentials中，与凭据一同按既有规则清除；不出现在订单详情、命令行或审计正文。Python仅为本次子进程传递专用环境变量，Go新增create-checkout专用 `--promo-code-env` 读取它，连接既有PromoCode选项。留空则不传上游；优惠码影响上游结账，平台服务费不变。没有平台优惠码库存、销售或自动选码。

Team网页请求指纹包含总席位、高级席位及优惠码，避免同一幂等键更改配置。Team API 使用新版本摘要，避免新旧默认高级席位数造成冲突；旧Team请求的幂等重放保留兼容摘要，仅用于查找已存在订单。非Team API空优惠码不改变旧请求指纹。其他流程收到优惠码明确拒绝，不静默忽略。后台账户专属价仅编辑当前可见套餐，保留隐藏的历史高级Team专属价。

订阅办理和结账链接使用同一单行套餐选择、左侧步骤与右侧确认布局；窄屏横滑套餐，表单与确认纵向展示。只生成链接的入口仍不付款，订阅续费选择保持默认支付后关闭。

测试使用隔离数据库及模拟上游，覆盖2+0、1+1、0+2和2+4席位、最少2席、优惠码加密及传递、幂等/费用不重复、旧套餐与价格保留。Go测试捕获实际Checkout请求体，核对default/prolite数量与总数及promo_code缺省，不请求真实上游。
