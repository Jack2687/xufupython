# 订阅办理网络重试

## 2026-11-05：Go 提链错误诊断

`cslive_go_checkout` 保留已知协议错误码及 `http_100`～`http_599`，以 `response_error_code` 写入技术日志；分类用于阶段说明，原码单独显示，不再用 `internal_error` 覆盖。记录来源为 Go 提链程序，可用时附进程退出码；HTTP 状态只从明确的 `http_NNN` 错误码提取。进程超时、无法启动、空输出及非 JSON 输出也有明确分类。

- `network_error`、网络超时、执行超时和 HTTP 408 进入现有付款前网络重试；次数读取 `payment.network_restart_limit`，间隔读取 `scheduler.retry_delay_seconds`，0 次仍关闭重试。
- HTTP 401 / Session 失效为授权问题，403 为访问拒绝，429 / 5xx 为上游繁忙；已有订阅、账号类型不符、验证未通过、格式异常及未知错误均单独归类。它们不自动加入网络重试白名单，不扩大现有重试范围。
- 只保留代码白名单，未知值统一 `redacted_error`；不记录原始 stdout/stderr、Session、Cookie、代理认证、账号、链接或错误正文。安全错误码及分类同时进入容器日志。
- 付款提交后的防重标记、已付款订单保护、链接/代理/账单复用及资金处理保持原有规则。历史失败订单不自动重跑，未保存的历史原始错误码无法补回。付款后的 Session 刷新次数和间隔不受此变更影响。

2026-11-03 用户要求：网络故障按配置重试；提链成功后复用该链接，从付款阶段继续，禁止重新提链。仅本地更新。

- 后台付款配置增加“付款前网络重试次数”，使用原有 `payment.network_restart_limit`，默认 2，范围 0～5；次数不含首次执行，0 关闭。保存时保留已有配置值。
- 等待间隔使用资源调度中的 `scheduler.retry_delay_seconds`。失败后在数据库记录次数和下次执行时间，重新排队，等待期间不占用执行线程；到时间才允许领取。暂停调度或关闭付款开关仍暂停领取。
- 提链尚未成功：按同一订单、原流程重新提链。提链成功：原结账结果及请求上下文加密保存；重试从付款阶段开始，复用链接、账号、账单快照及代理会话，不增加出口 IP 探测，不切换供应商。
- 自动重试仅覆盖连接、代理隧道、DNS、超时等网络故障。403 验证拦截、拒付、参数错误、失效链接和会话过期不在此范围。
- 重试期间不重复冻结或扣服务费，耗尽次数后按原失败逻辑解冻一次。每次重试的原因、次数、间隔、复用链接与执行轮次写入监控记录。
- 提交付款确认前，先持久化 `payment_submit_started_at`。提交后网络断开、结果不明时保留原交易为待核实，不重走付款；已付款成功的订单也不重新执行。此边界避免把“没有收到成功响应”当成“没有扣款”。
- 当前本地只保留 gener，继续沿用原重试调度规则和订单流程归属限制。cslive 已按后续要求删除，不再有对应执行器。

持久字段位于 `subscription_runs`：`checkout_checkpoint_enc`、`network_retry_count`、`network_retry_at`、`payment_submit_started_at`。旧订单不会因添加字段自动重跑。

验证使用临时 PostgreSQL 和模拟上游：网络失败后复用链接、配置次数耗尽、关闭重试、未知或已删除流程归属不被领取、费用只结算一次、已付款/付款结果不明不重付、403 不重试，以及上下文/账单/代理会话保留。
