# Plus 与 Pro 50x（Pro Max）

新增 `plus`、`promax` 两个套餐，初始服务费各 100 积分（数据库最小单位 10000）。初始化仅插入缺少的套餐；已有名称、价格、启用状态及旧订单保持不变。

本次只开放 `cslive_go_direct_pay`：Go 提链 + HTTP 直连付款 + Go 付款成功后续。复用既有映射：`plus` → `chatgptplusplan`，`promax` → `chatgptpromax`。两个 Go 模型目录和付款后核实已包含对应标识；提链、付款、收尾执行器源码保持不变。每单代理 session、后台账单抽取、付款防重及取消续费选项沿用现有实现。

追加订阅地区管理后，该流程的受理与提链参数读取改为使用 `orders.region_snapshot`；提链协议、HTTP 付款及 Go 收尾源码保持原样。后台 `/admin/regions` 支持名称、国家代码、币种、排序及启用状态，初始七地区仅首次插入 settings.regions；删除后重启不恢复。当前仅指定流程接受新增地区与自定义币种；其他流程仍按原地区及币种执行，同时遵守地区禁用。已受理订单使用原快照，旧订单使用原代码内默认值，不读取后续变更的配置。

代理地址编辑不再将未到期的容量租约视为执行锁。资源修改只影响后续获取，已创建的订单代理会话和已获取的客户端地址保持原样；已有检测结果通过凭据版本比较防止覆盖新资源。删除资源的占用保护保留，不清除有效租约。

公开套餐目录、会员价格、报价与新订单受理统一按流程限制新增套餐；管理员可设置名称、价格、启停及账户套餐专属价。其他流程的四个已有套餐保持原有规则。配置切换后的 API 幂等重放仍返回原订单，已排队订单继续按原流程归属执行。

后台长短链配置加入 Pro Max，默认长链；Plus 保留已有设置。旧配置缺少 Pro Max 时读取默认值，不写回数据库；旧客户端保存时保留已配置的 Pro Max 类型。Plus 的“尚未上架”提示仅在本次指定流程移除。

客户 API 1.4.0：`GET /api/v1/catalog` 返回 `plus` / `promax`，报价和创建订单使用相同 `product_id`。`workflow=link` 仅提链；`workflow=subscription` 按原流程付款及收尾。更新 `/api/openapi.json`、`/docs#product-ids`、两套餐分别的订阅和仅提链示例。客户端不提交 `plan_name`，也不修改 Session 内原账号的套餐字段。

验证使用隔离数据库和模拟上游：覆盖套餐插入幂等、后台自定义价格保留、目录和报价、两工作流、API 与网页入口、服务费冻结防重、切换流程后的幂等重放、下架、旧配置及 Go 参数传递。没有真实付款或取消续费测试。
