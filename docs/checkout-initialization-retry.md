# 提链初始化重试与诊断

Go 提链返回 `device_id_missing` 时，尚未生成结账结果且尚未提交付款的订单可进入既有重试队列。次数读取 `payment.network_restart_limit`，间隔读取 `scheduler.retry_delay_seconds`，与网络重试共用每单次数预算；0 表示不重试。重试从首页初始化开始，保留订单、账单、冻结积分、代理会话及原到期时间，不重新申请代理、不延期。

每次失败记录首页 HTTP 状态、是否返回跳转、请求前/响应中的设备 Cookie 是否存在、读取后的设备标识是否存在、响应格式和字节数，以及是否检测到验证页面特征。验证特征是有限规则检测，未检测到不代表页面正常。诊断只允许类型受限的布尔值、整数和格式枚举，不保存页面正文、Cookie、Token 或跳转地址。Go CLI、Python 日志和后台技术详情均保留这些安全字段。

达到次数上限后显示“初始化失败：未获取到设备标识”，走原有失败与积分解冻逻辑。已生成链接或已提交付款的订单不因此重新提链或付款。401、403、已有订阅及验证失败等其他错误的重试规则不变；付款后刷新 Session 的次数和间隔不变。

此次不修改设备标识的获取/传递方式，不生成替代设备标识，不自动重跑历史失败订单。测试使用模拟响应和独立数据库，不进行真实提链或付款。
