# 邀请与界面改进

后台邀请管理与客户伙伴计划使用同一邀请关系和奖励账本。默认开放，首单实际平台服务费的 5%，可设 1%～30%。仅直接邀请，注册时绑定，不允许客户改绑；每位被邀请人终身仅一次。

仅配置开启时新建的订阅订单建立资格快照，保存当时比例。已有成功订阅和历史订单不补发；付款成功、订阅已生效、服务费已结算才可奖励。新表唯一约束及独立事务锁防止并发或重复入账，奖励与积分账本在同一事务提交。正常一分钟内结算，不调用任何上游付款接口，不改办理执行路径。仅提链不奖励；零服务费奖励为零，仍消耗一次资格。关闭开关仅影响新建订单。

退款按服务费净额撤回相应奖励，精确到 0.01 积分，向下取整。只扣可用积分；已使用或被冻结的部分记录为待扣回，后续余额足够时继续处理。冻结服务费不受影响。未完成扣回会在后台及伙伴计划明示。奖励不作为充值，不可提现。

兑换码列表继续脱敏；管理员通过单个复制或批量复制显式读取所选完整码，按当前列表顺序，每码一行。包括停用码，复制不改变状态；完整码不写审计文本。原 TXT 导出有效码规则保留。

竖向滚动条隐藏，滚轮、触摸和键盘滚动保留；Chromium 的横向表格滚动条保留。Firefox 不支持分轴隐藏，因此隐藏滚动条但仍支持横向滚动。

充值表采用独立列宽，日期不拆行，窄屏为卡片。办理阶段显示结束日期时间，缺失则明确未记录，不用开始时间或更新日期推测。

技术日志仅改前端投影：同一请求的开始和返回合并，可确认对应的阶段及业务记录折叠为原始证据；不同轮次、请求尝试和失败保留。付款后等待与刷新授权明确区分。列表分为标题/状态与日期/耗时/HTTP 两行；正在执行才转圈，完成后显示结束时间。原始日志、后台记录、付款、刷新、重试逻辑均不变。
