# 兑换码事务与管理

兑换、生成和批量操作的同步数据库工作在受控线程池执行，不阻塞异步事件循环。兑换码事务局部设置锁等待 3 秒、SQL 执行 10 秒；超时或死锁整体回滚，返回 503，客户可稍后重试。其他业务事务的超时不变。

兑换拿到用户行锁后复查账号启用及软删除状态。余额、流水、码已使用状态同事务提交，重复提交不能重复入账。

管理列表 `/api/admin/codes` 支持 `page`、`page_size`（1～100）、`q`（标识/批次/兑换邮箱）和 `status`（active/used/disabled/expired），返回 total、has_more。默认每页 100 条，移除历史 1000 条截断。

有效状态优先级为已兑换、已停用、已过期、可用。复制保留历史查看能力，发放导出只包含有效未使用码。批量接口保留原返回字段，并增加 changed/skipped，审计记录真实处理数量和目标 ID，不写完整兑换码。

数据库测试使用独立临时库及关闭的业务执行器，覆盖等待锁期间健康请求、账号停用/删除竞态、超时回滚重试、账本写入失败、1000 条以上的分页搜索及过期状态。
