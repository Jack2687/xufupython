# 付款后 HTTP 上下文、重试与错误证据

2026-11-03，按用户要求对照 `cs-live-source.zip` 的付款后实现完成本地修改。
修改前备份位置见 `.local/followup-context-backup.txt`。

## 请求上下文

- 每个订单独立建立 `OrderHTTPContext`。提链仍使用原有 curl 请求、原套餐及长链逻辑；记录实际发送的客户端/语言请求头和实际响应的 ChatGPT Cookie。
- 仅将 ChatGPT 域、正确路径且未过期的 Cookie 传入后续核实、刷新及取消续费客户端。禁止把 ChatGPT 凭据传给 Stripe；并发订单通过 ContextVar 隔离。
- 收尾中的真实 Cookie 更新随阶段写入加密 checkpoint，恢复时重建，已删除的 Cookie 不复活。AT 仍按原有 401 刷新、取消前主动刷新的规则更新。
- 延续同一订单保存的代理端点、session 和有效期，不增加出口 IP 查询或一致性比较。
- 对齐的是实际 HTTP 会话状态，不复制包里的合成浏览器指纹、遥测或挑战生成代码。底层依旧是原提链 curl、付款后 httpx，不声称已逐字移植 Go HTTP/TLS 客户端。

## GET 故障重试

与参考包相同，仅 GET 的网络错误和 408、429、500、502、503、504 最多尝试 3 次，间隔 0.5 秒、1 秒。每次请求和等待均单独记录；等待后仍检查本单代理会话有效期。

401 仍交给原业务刷新逻辑；403、普通 404 和其他错误不触发此层重试。套餐尚未生效的最多 5 轮、2 秒间隔逻辑保留。POST 不进行底层自动重发；取消请求响应丢失后仍先复查状态，再按原有限次数策略处理。

## 错误证据

付款后失败响应记录：HTTP 状态、响应类型、上游错误 code/type、脱敏 message/detail、HTML 标题和可见文本摘要、Request-ID、CF-Ray、明确的 challenge 响应标记、单次耗时、请求次数及重试等待时间。

错误体读取上限 64 KiB，超限只记录截断标记；文本字段最多 500 字符。日志不保存原始响应、请求头、Cookie、AT、Session、代理密码、完整 URL、邮箱或卡号。正常 Session 刷新响应不记录正文。Cookie 只进入加密 checkpoint。

前端将付款回跳请求标为“访问付款回跳页”，不再用这一条 HTTP 200 表示订阅已生效；历史订单缺失的错误响应不补造。

## 验证与范围

使用内存 HTTP 和独立临时 PostgreSQL 验证 Cookie 交接及恢复、并发隔离、故障重试、403 停止、凭据脱敏、费用不重复结算和付款成功状态不被收尾失败覆盖。未执行真实付款或自动重试历史订单。本次仅本地修改，不推送或更新正式环境。
