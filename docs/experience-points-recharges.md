# 2026-11-04 体验与账户记录更新

付款配置增加 `cslive_go_visit_return`、`cslive_go_refresh_before_renewal`，默认 true，旧客户端省略时保留已保存的值。仅 cslive_go_direct_pay 传递这两个选项；gener 和完整 cslive 流程不受影响。付款后等待、首次强制刷新、空 Token 重试次数和间隔保留。关闭取消前主动刷新时复用本单最新凭据，若查询或取消明确返回 401，则按原配置刷新、持久化并复核；取消写入仍不超过原上限。

订单阶段通过 PostgreSQL 提交后的 NOTIFY 和认证 SSE 推送。通知仅包含订单 ID，客户仅收到自己的订单变化；每次事件及心跳重新检查会话。断线重连、返回页面时重新同步，手动刷新保留。订单列表、详情和个人页不再按固定间隔请求阶段。管理详情显示真实开始时间，同轮同操作开始/完成合并且保留原始诊断；在途阶段使用动画，已结束记录停止动画。客户详情继续隐藏管理技术记录。

账户展示单位统一为积分，删除用户指定的 API 计价说明。整数存储与展示除以 100 的比例不变，旧 API `unit=cent_R` 值保持兼容，描述改为积分最小单位。上游银行卡币种不变。各处可用余额显示 `balance-frozen`；资金流水的可用变动按相邻记录的可用余额之差计算，服务费冻结和结算不重复显示扣减。

充值记录读取原账本中的兑换入账和人工充值申请。历史兑换立即可见，仅显示兑换码脱敏标识，不解密或返回完整兑换码，不制造充值申请或重复入账。列表展示来源、支付费用说明、可用/冻结变动、入账后余额、关联记录和时间；待审核申请仍可撤回。`/api/v1/topups` 保留原人工充值申请接口含义。

公告中心提供顶部未读数量、全部/未读切换、展开阅读和全部已读。公告正文或有效期修改后重新视为未读，已读状态按账户保存在当前浏览器。未来、过期及未发布公告不展示。

风控监控提供查询、日期、分类、级别、处理状态和服务端分页；同一客户/IP/分类一分钟内合并计数。核查与解除限制分别执行，保留现有风控策略。普通客户不显示管理顶部标识；管理页面跳转和后端权限分别检查，API 密钥不能访问浏览器或管理接口。代理管理移除重复付款配置入口。

验证使用临时数据库、离线上游和独立 UI 服务；不使用真实付款、取消续费或删除客户订单作为测试。正式发布按父目录 runbook 保留生产配置、数据、密钥和其它容器。
