# 付款后网络诊断

Go 付款后流程的 Session 刷新、订阅状态查询、取消续费和续费复查，继续使用原订单代理和原来的超时、重试规则。本次仅增强观测，不新增出口探测或上游请求，不补跑历史订单。

支付全监控 → 订单完整记录 → 技术日志，可查看：

- 代理协议、连接代理和隧道协商耗时；HTTPS 代理另有代理 TLS 握手耗时。HTTP CONNECT 状态码与上游 HTTP 状态码分开记录。
- 能观测到的 DNS、TCP、TLS 耗时；连接是否复用及空闲时间。自定义 TLS 拨号器可能不触发握手钩子，未测得的值不补零，不推测。
- 请求是否写出、是否收到响应字节、响应头是否完整、已读取正文长度。正文读取失败也保留已收到的状态码（诊断字段 response_status）。写出请求不等于上游已收到或完成处理。
- 网络错误的固定分类（DNS、证书、超时、连接重置/拒绝、提前断开、代理协商等）、失败操作、本次超时预算及流程剩余时间；区别请求时限、流程总时限和底层超时。
- 每次查询的尝试序号、是否将重试、实际等待时间，沿用现有字段。

例如 request_written=true、response_started=false、network_stage=response_headers 表示请求已在本地写出，但未收到响应。即使代理隧道已建立，也无法单凭此信息判定供应商后续转发正常或上游已处理取消。取消结果仍需查询确认。

只记录固定枚举、数值和布尔值；不输出原始网络错误、请求/响应正文、Token、Cookie、代理地址或账号密码。Python 两个 Go 适配器共用持久化白名单，管理员页面展示中文说明。无数据库迁移；历史日志没有的新字段不会回填。

验证使用回环模拟代理与受信任测试证书的本地 HTTPS 服务，覆盖代理 407、GET 三次/POST 一次策略、响应头/正文超时、部分响应和敏感值过滤。没有真实付款、Session 刷新或取消验收。
